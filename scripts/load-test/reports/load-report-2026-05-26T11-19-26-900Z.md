## Architektur-Hinweise (Code-Review, statisch)

1. **`GET /fleet-driver/v1/market-rides`** ruft `listRides()` → volles `SELECT * FROM rides` pro Poll — skaliert O(N) mit Gesamtfahrten.
2. **Fahrer-Poll ~2,5 s** × aktive Fahrer → multipliziert DB-Last; fehlender Index/Filter auf offene Sofortfahrten.
3. **`PATCH /rides/:id/status`** triggert Finance-Snapshot (`upsertRideFinancialSnapshot`) bei Cancel/Complete — teure Transaktion unter Last.
4. **WebSocket-Hub** in-process (`ws` auf gleichem Node-Prozess) — keine horizontale WS-Skalierung ohne Sticky Sessions/Redis.
5. **PM2 Single-Instance** (typisch `onroda-api`) — CPU-bound Express + WS auf einem Kern.
6. **Nginx** TLS + Proxy ist selten der erste Engpass; Upstream-Timeouts bei langen DB-Queries relevanter.
